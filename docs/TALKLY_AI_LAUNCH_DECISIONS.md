# TALKLY AI 런칭 결정 대기 항목

현재 확정: TALKLY 내부 별도 페이지, 영어 먼저, 3분 체험, 하루 10분·30일 13,900원 수동 재결제, 학습 요약 3개월, 생각 중 버튼 없이 자동 대기. 운영 공개·실결제는 아직 활성화하지 않습니다.

## 초기 이용 대상 — 성인 먼저로 확정

사용자가 채팅 선택지에서 **성인 먼저**를 선택했습니다. 초기 대상은 한국 기준 만 19세 이상 본인 이용으로 정했습니다. 미성년자·자녀 이용은 후속 개발 범위로 보류합니다. 기존 TALKLY 회원가입은 학생/학부모 역할을 선택하고 휴대폰을 인증하지만 성인 여부나 생년월일을 확인하는 AI 전용 가입 단계는 없습니다. 학부모가 본인의 children 행과 연결된 학생 계정을 생성하는 기존 경로는 있으며, 이 연결을 AI 보호자 동의/관리 범위에 사용할 수 있는지 추가 설계가 필요합니다.

AI는 현재 auth user별 회원·이용권·대화 기억을 관리합니다. 보호자가 자녀의 사용량/결제/리포트를 어디까지 관리할지, 보호자 본인의 AI 이용권과 자녀 이용권을 어떻게 구분할지는 미확정입니다. 기존 수업의 학부모 계정 연결을 AI 가입 동의로 자동 간주하지 않습니다.

선택 후 확인할 항목: 이용 대상 범위, AI 학습자 본인과 결제자 구분, 기존 children 연결 재사용 여부, 필요한 가입 안내·동의와 접근 제어. 관련 정책은 현재 법령·제공업체 지침을 확인해 설계하며 여기서는 법적 충족을 주장하지 않습니다. 기존 회원·권한·수업 데이터는 사용자 결정 없이 변경하지 않았습니다.

## 현재 적용 방식과 한계

가입 시 성인 본인 이용 확인과 AI 안내 동의를 받고 `2026-10-25-v2-adult19` 동의 버전·시각을 기록합니다. 생년월일·신분증은 추가 수집하지 않습니다. 서버의 현재 동의 확인을 통과해야 회화·이용권·요약 저장을 사용할 수 있으며, 기존 가입자는 새 안내를 확인해야 합니다. 동의 갱신은 체험 시간·이용권·정지 상태·기억을 초기화하지 않습니다. 기존 토클리 수업/회원가입은 변경하지 않았습니다.

**자기확인은 실제 연령 인증이 아닙니다.** 정식 공개 전 연령 확인 수준·본인인증 제공업체/비용·우회 대응을 확정해야 합니다. 현재 코드만으로 미성년자 접근을 확실히 배제하거나 법적 요건을 모두 충족한다고 주장하지 않습니다. 보호자 계정이라는 이유로 성인으로 간주하지 않습니다. 이전 동의 회원도 새 요약 저장 철회는 가능하게 유지합니다.

참고: 민법 제4조(성년) 국가법령정보센터 https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1004361007 ; OpenAI under-18 API guidance https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance . 후자는 어린이 개인정보를 처리할 때 별도 zero data retention 요건을 안내하므로 미성년자 확대 전 제공업체 설정 확인이 필요합니다. 이 문서는 정책 설계 기록이며 법적 적합성 확인서가 아닙니다.


## 2026-10-25 취소·환불 초기 운영 및 결제 확인

사용자는 채팅 선택지에서 **관리자 확인 후 처리**를 선택했습니다. 관리자 검토 방식으로 운영하며 자동 환불 금액 산식은 정하지 않았습니다. 구체적인 환불 기준/신청·검토 화면/실제 토스 취소/이용권 회수 처리는 아직 미구현이며 유료 판매 전 확정할 항목입니다. 이번 선택을 실제 환불 실행이나 정책의 법적 적합성 확정으로 해석하지 않습니다. 이용 안내에도 준비 상태를 반영했습니다.

독립적인 결제 확인 안정성 작업을 완료했습니다. 확인 중 재시도 버튼 비활성, 50초 응답 제한/화면 이탈 시 요청 취소, 같은 주문 재확인 안내, 정상 성공 후에만 URL의 결제 파라미터 제거를 추가했습니다. 이미 이용권에 반영된 주문은 새로 반영했다고 표시하지 않습니다. 서버 maxDuration=60, 기존 제공업체 조회 15초/승인 20초와 같은 멱등키를 유지하고 GET/POST 캐시를 끕니다. 토스 결제 키/주문번호 허용 범위와 빈 키를 검증하고, paid 빠른 응답도 키/금액/이용권 날짜를 확인합니다. 404 이외의 조회 오류에서는 승인 POST를 추가하지 않습니다. provider DONE/금액/통화/주문/키/승인 시각 및 이용권 반영 날짜가 유효해야 성공합니다. 승인 후 이용권 DB 실패는 미확인 상태로 남겨 같은 주문 조회를 재시도하게 합니다.

실제 라우트/클라이언트 effect의 가상 테스트로 결제 OFF 차단, 소유자 조건, 멱등 재확인, 조회 장애 시 승인 생략, 변조/취소 상태 차단, 이용권 반영 재시도, 대기/타임아웃/이탈 처리를 확인했습니다. 실제 토스 승인·취소·환불/테스트 결제나 새 비밀 키는 사용하지 않았고 운영 결제 플래그는 OFF입니다. 공식 객체/상태/파라미터 참고: https://docs.tosspayments.com/reference .

### 환불 관리자 검토 구현 범위 (2026-10-25)

회원 요청 접수와 관리자 검토 상태/변경 이력 저장을 구현했다. 접수 및 검토만으로 금액/결제/이용권을 변경하지 않는다. 환불 가능 금액·실제 취소 실행·이용권 중첩 조정·완료 통지는 미구현이며 판매 전 결정해야 한다.
