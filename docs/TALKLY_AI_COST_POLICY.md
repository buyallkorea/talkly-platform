## 연결 요청 보호

`20261025122413_talkly_ai_connection_rate_limit` 적용. 회원별 서버 측 시간 기준 최근 60초 6회, 최근 1시간 30회의 일반 연결 시작 요청을 허용합니다. 회원 행 잠금으로 여러 창/서버 인스턴스에서도 한 기준으로 판정합니다. 요청 제한은 무료/유료 이용 시간과 독립적이며, 제한 응답은 새 예약과 OpenAI 요청 전에 HTTP 429/Retry-After/한국어 안내를 반환합니다. 제한 중 반복 요청은 대기 시간을 연장하지 않습니다. 종료·정산은 제한하지 않습니다. 보호 DB 요청은 최대 3초로 제한하고, 오류 시 새 음성 요청은 503으로 중단합니다.

정상 자동 갱신을 보호하기 위해 서버에 기록된 직전 종료 paid lease가 60초 이상 예약됐고 끝까지 사용된 경우(최대 2초 여유), 예약 종료 경계 및 종료 후 30초 안에 한 번은 카운터에 넣지 않고 허용합니다. 같은 이전 연결을 다시 사용할 수 없으며 브라우저의 재연결 플래그를 신뢰하지 않습니다. 예외 허용 후에도 기존 예약 함수가 일일 한도/이용권/중복 연결을 검증합니다. 짧은 연결과 실패한 미등록 연결은 이 예외의 근거가 되지 않습니다. 초기 기준의 실제 불편 여부는 오픈 후 사용 흐름으로 조정할 항목입니다. 정상 사용에서 제한이 전혀 없다고 보장하는 값은 아닙니다.

표에는 사용자별 최대 30개 시간값과 마지막 갱신 근거 ID만 보관합니다. IP/장치/연락처를 추가 수집하지 않습니다. 1시간 지난 시간값은 다음 판정 시 제거하며, 활동이 없는 행의 물리 보관 기간은 정식 기술 기록 정책에 포함할 별도 항목입니다. 요약 3개월 정책을 임의로 적용하지 않았습니다. 일반 클라이언트는 테이블/RPC에 접근할 수 없습니다.

회원 정보 응답에서는 화면에서 사용하지 않는 이전 대화 원문 필드를 제외했다. 서버의 음성 연결 지침은 기존과 같이 직접 회원 기억을 읽으므로 회화 연속성은 유지한다. 브라우저로 보내는 중복 데이터 감소이며 모델 사용료 절감 수치로 해석하지 않는다.

## 느린 연결에서 기억 저장 대기열 압축 (2026-10-25)

이미 전송한 저장은 직렬 순서로 완료를 기다리고, 아직 전송하지 않은 같은 회화의 스냅샷은 최신 최대 20개 발언으로 합친다. 다른 회화의 ID와 내용은 합치지 않는다. 저장 실패 후에도 다음 대기 작업은 진행하고 각 호출자에게 결과를 반환한다. 기존 API 제한 시간·회화 모델·응답 대기·종료 정산 경로는 유지했다.

가상 지연 테스트에서 첫 저장을 보류한 동안 99개 후속 스냅샷이 쌓인 경우 총 두 번(첫 내용/최신 내용) 전송되는 것을 검증했다. 이는 느린 연결의 중복 DB 저장 대기를 줄이는 결과이며 실제 API 청구 비용 절감률이 아니다. pagehide keepalive 저장은 기존 독립 경로이며, 서버 완료 전 네트워크가 끊기거나 요청이 역순 도착하는 경우의 완전한 전달 보장은 하지 않는다.

## 미연결 예약 시간 복구 및 실행 시간 여유 (2026-10-25)

연결 등록을 원자적으로 차단한 뒤 서버 등록 통화 ID가 없는 예약은 실패 예약으로 정산한다. 예약만 남은 채 만료되어 나중에 정리되더라도 무료 체험/유료 일일 시간이 소모되지 않는다. 실제 통화 ID가 있으면 hangup 확인 후 기존 실제 연결 경과 시간 정산을 유지하며, failed 플래그만으로 실제 통화 시간을 되돌리지 않는다. hangup 실패는 예약을 계속 유지한다.

서버 준비가 10초를 넘겨 이미 실행 시간 여유가 줄어든 경우 신규 provider 연결을 만들지 않고 알려진 미연결 예약을 복구한다. 정상 lease는 최대 240초와 기존 응답 대기를 유지한다. 플랫폼 강제 종료나 독립 supervisor 부재를 모두 해결한 것은 아니다.

실제 종료 helper와 독립 PostgreSQL을 함께 실행해 만료된 미연결 trial/paid 복구, 중복 정산, 연결된 통화의 정상 차감, 종료 실패 시 예약 보존을 검증했다. 가상 단조 시계 테스트로 준비 지연 시 provider 호출/관찰 시작 전에 중단·정리되는 것을 확인했다. 실기기/런타임 검증은 오픈 후 진행 예정이다.

## 독립 미연결 복구와 짧은 전송 장애 (2026-10-26)

매분 DB 작업이 call_id 없는 만료 connecting/closing 예약만 최대 100건 기존 실패 정산으로 복구한다. 회원→세션 잠금·조건 재확인·멱등 정산을 유지한다. 등록 통화의 종료 감독이나 미등록 원격 통화 종료를 대체하지 않는다. 실제 cron 첫 정상 실행을 확인했으며, 운영 만료 미연결 예약은 검증 당시 0건이다.

브라우저 peer의 일시 disconnected 상태는 최대 3초 기존 연결 복구를 기다린다. connected로 돌아오면 새 provider 연결·요약·인사 없이 이어가며, 반복 이벤트는 대기를 연장하지 않는다. 실패/종료·마이크 종료·채널 실패와 원래 lease 만료는 기존 정리 경로를 유지한다. 대기 중 서버 연결 시간은 계속 계산되며 추가 무료 시간은 만들지 않는다. 가상 이벤트에서 중복 종료·취소·이전 연결의 이벤트 무시를 확인했으나 실기기 복구 성공이나 실제 비용 절감액은 미측정이다.
