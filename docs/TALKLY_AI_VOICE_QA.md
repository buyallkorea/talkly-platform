# TALKLY AI 실제 음성 검증표

상태: **실제 마이크 검증 미실행**. 아래 항목은 코드/가상 이벤트 테스트 통과와 별도로 확인해야 합니다. 개발 preview와 유료 결제 OFF 상태에서 진행합니다. 운영 수업·결제 데이터에 테스트 주문을 만들지 않습니다.

## 순서

1. PC Chrome에서 마이크/스피커를 확인하고 AI 가입·3분 체험을 실행합니다. 일반 회원은 총 3분, 관리자 별도 테스트 이용권은 하루 10분이므로 구분합니다.
2. 아래 회화 사례를 실행하고 화면에 표시된 문장, AI가 말한 내용, 기다린 시간, 오류·중단 시점을 기록합니다. 원음 업로드·녹음 저장을 요구하지 않습니다.
3. 모바일 Safari 또는 Chrome에서도 권한·재생·일시정지를 확인합니다.
4. 관리자 테스트 이용권으로 10분 연결과 약 4분 단위 갱신을 확인합니다. 현재 갱신 시 짧은 끊김이 가능하며 자연스러운 전환 여부는 별도로 평가합니다.

## 코드 검증으로 확인한 범위

`node tests/talkly-ai/turn-coordinator.mjs`: 실제 클라이언트 이벤트 처리 함수를 결정적 시계·가상 타이머와 함께 실행합니다. 음성 확정 뒤 자동 추가 대기, 짧은/미완성/긴 답변의 대기 시간, 발화 재개 시 예약 응답 취소, 새 음성의 확정 대기, 중복 이벤트, 무입력 침묵, provider 오류 시 중단을 확인합니다.

**생각 중/답변 준비됐어요 버튼은 제거했습니다.** 의미 기반 VAD low 뒤 기본 1.5초, 짧은 답변 2.5초, 미완성 접속 표현 3.5초, 긴 문장 0.8초의 추가 여유를 적용합니다. 최근 3개 발언 중 짧은 답이 2개 이상이면 기본 여유를 2.2초로 둡니다. 실제 발화 감지·전사 지연은 여기에 더해질 수 있습니다. 이 수치는 초기 조정값이며 객관적 수준 평가가 아닙니다. 응답 전 다시 말하기 시작하면 예약을 취소하고 해당 새 입력 확정을 기다립니다. 텍스트를 직접 보내면 추가 음성 대기는 적용하지 않습니다.

이 방식은 무제한으로 생각을 읽거나 모든 긴 침묵을 정확히 판단하지 못합니다. 실제 기기·억양·오디오 지연·provider 접근·10분 watchdog과 갱신 경계는 미검증이며 실사용 피드백을 통해 대기 시간을 조정해야 합니다. 시간 예약·환급·요금제·DB는 변경하지 않았습니다.

## 연결 장애 자동 종료 검증

`node tests/talkly-ai/connection-failures.mjs`는 실제 클라이언트의 실패·종료·로컬 정리 함수와 채널/장치 이벤트를 추출해 실행합니다. 채널 닫힘/오류, 마이크 종료, peer 연결 단절, autoplay 거부, 연결 준비 중 실패, 정상 종료 후 늦은 이벤트와 오래된 재생 실패를 검증합니다. 마이크·peer 정리, 서버 정산 요청 1회, 요약이 정산 성공 뒤에만 진행됨을 확인합니다. lease 만료 직전 원격 종료는 자동 갱신을 유지합니다.

네트워크가 완전히 끊겨 종료 API도 전달되지 않으면 서버 정산은 즉시 보장되지 않습니다. 클라이언트 장치는 정리하고 종료 확인 실패를 표시하며, 서버 watchdog/다음 접속의 만료 세션 복구가 처리합니다. 이 상황의 실제 시간 정산·사용자 복구는 실사용 검증이 남아 있습니다.
