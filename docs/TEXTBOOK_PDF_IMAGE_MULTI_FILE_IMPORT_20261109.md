# TALKLY 교재 PDF/이미지 페이지별 등록 개선

2026-11-09 사용자 요청 및 운영 사전 점검을 바탕으로 작성.

## 현재 시스템 사전 확인

- 기존 교재 등록 단위: 대표 `textbooks` 아래의 `textbook_volumes`.
- 기존 수업용 페이지: `textbook_pages(volume_id,page_number,page_image_url,page_width,page_height)`. 수업/관리자 뷰어는 이 테이블의 페이지를 사용하므로 뷰어 코드를 수정할 필요가 없다.
- 기존 교재는 Storage `textbook-files` 원본 + `textbook-pages` 변환 이미지. 모두 private bucket.
- 확인 시 104권 중 1권이 정상 생성(101페이지), 103권은 draft. **기존 101페이지 및 핫스팟 보호를 위해 내용이 있는 권은 덮어쓰지 않는다.**
- DB의 `original_file_type`은 CHECK 제약이 없는 text 필드이므로 `pdf`, `images`, `mixed`로 기록 가능. DB migration 불필요.

## 개선한 화면

- 관리자 > 교재 수정 > 권(Volume) 선택에서 PDF/JPG/JPEG/PNG/WEBP 여러 파일 선택.
- 한 페이지씩 별도 PDF로 분리된 파일, 한 페이지씩 별도 이미지로 분리된 파일, 여러 페이지 PDF/이미지 혼합 파일도 가능.
- 파일명 자연 순서(1,2,10)로 자동 정렬하고 위/아래 버튼으로 수동 순서 조정.
- 각 파일은 브라우저에서 private Storage에 업로드하고, PDF는 서버에서 페이지별 PNG로, 이미지는 검증/PNG로 변환.
- 파일 하나 처리 완료 후 다음 파일로 진행. 여러 파일을 한 번의 서버 함수에서 변환하지 않아 한 페이지씩 나뉜 교재에도 대응.
- 모든 페이지를 변환한 뒤 `textbook_pages`에 연속적인 `page_number`를 확정 저장하고 Volume에 총 페이지 수와 형식 갱신.
- 한 번에 최대 400파일, 합계 최대 400페이지, 원본 각 파일 최대 60MB, 페이지당 3,500만 픽셀 제한.
- 처리 중 페이지를 나가거나 새로고침하면 임시 작업이 완료되지 않을 수 있으므로 완료 전 이동 금지 안내.

## 안전성 및 제약

- 실제 등록 전에 관리자의 로그인 및 role 확인(기존 TALKLY 인증).
- 원본/페이지 Storage 경로에 교재ID·권ID·batch UUID를 포함하고 prefix/확장자 검증.
- 이미 `textbook_pages`가 있거나 ready이거나 원본 파일이 지정된 Volume은 등록 불가.
- 각 파일 렌더 실패 시 해당 작업에서 생성한 페이지 이미지만 제거하고, 전체 실패 시 업로드한 임시 객체 정리 시도. 이전 교재의 자료를 삭제하거나 덮어쓰지 않음.
- PDF.js는 Canvas global 설정 후 import; 기존 PDF 변환 스케일 1.5 유지.
- 파일 크기, 개수, 페이지 번호, 이미지 크기, 요청 origin을 검증.
- 교재 저장 기능은 기존 `textbook_pages` 및 `textbook_volumes`만 사용. 학생·강사 뷰어, 오디오/화이트보드, 교재별 진도 기록 및 다른 사이트 데이터에 코드 변경 없음.

- Vercel Preview 빌드 성공 여부 확인 후 운영 배포.
- 실제 관리자 계정으로 다양한 파일 등록 및 학생·강사 강의실 교재 보기 테스트는 별도의 승인된 테스트 권/수업이 필요하다. 기존 101페이지 운영 자료에는 테스트 쓰기 금지.
