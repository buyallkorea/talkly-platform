## 서로 다른 세 가지 이용 방식

1. **일반 가입 혜택:** 모든 AI 회원에게 결제 없이 총 3분, 계정당 1회. 날짜 변경·가입 재시도로 초기화되지 않습니다.
2. **정식 이용권:** 하루 10분, 30일 13,900원, 수동 재결제. 유효한 이용권이 있으면 정식 일일 한도를 먼저 사용합니다.
3. **관리자 개발 테스트:** preview에서 관리자 본인만 켤 수 있는 24시간 검증용 이용권. 일반 회원 혜택이나 판매 요금제가 아닙니다.

## 남은 검증·개발

실제 음성·기기·대기시간 검증, Vercel 접속/로그 권한 확인, 안전 제한의 서버 통제, 월말 리포트의 자동 발행·알림과 실사용 검증, 결제 취소·환불과 이용권 회수 연동, 정식 정책 및 미성년자 가입·동의 처리가 남아 있습니다. 빌드·가상 테스트·DB 검증이 통과했다는 이유로 실제 음성 검증까지 완료됐다고 보지 않습니다.

## 2026-10-25 월간 리포트 저장 방식 결정

사용자가 채팅 선택지에서 **학습 요약만 저장**을 선택했습니다. 전체 대화·음성 녹음은 추가 보관하지 않습니다. 기존 최근 20개 발언 기억은 유지합니다.

- `/talkly-ai/reports`에서 별도 동의 후 시작한 회화만 요약합니다. 동의 이전 기록을 소급 분석하지 않습니다.
- 연결 구간 종료 후 최대 100개 발언(발언당 500자)을 일시적으로 분석하고 학습 요약만 저장합니다. 요약은 `gpt-4.1-mini`, `store:false`로 생성합니다.
- 월별 학습일·정산 연결시간·주제·실제 등장 표현·교정·다음 연습을 제공합니다. 표현과 교정 인용은 입력 대화에 있는지 검증합니다. 임의 점수·발음 점수·등급·향상률은 생성하지 않습니다.
- 현재 월은 중간 기록, 지난 월은 월간 정리로 조회합니다. **월말 자동 발행·이메일·푸시 알림은 아직 구현하지 않았습니다.**
- 요약은 자동 갱신을 막지 않도록 비동기로 저장합니다. 창 닫기·통신 장애·API 실패·동의 이전 구간은 누락될 수 있어 반영 구간 수를 표시합니다. 매우 많은 기록은 최근 1,000개 요약으로 제한하고 이를 표시합니다.
- 요약 저장 켜기·끄기와 재동의 처리를 구현했습니다. 학습 요약은 저장 시점부터 3개월 보관 후 자동 정리합니다. 보관 중인 기록의 개별 삭제 UI는 추가 개발 대상입니다. 실제 대화 요약 품질과 모델 접근은 실사용 검증이 남아 있습니다.

## 2026-10-25 재개: 학습 요약 저장 설정 보완

- 월간 리포트에서 학습 요약 저장을 켜거나 끌 수 있습니다. 끄면 새 요약 저장만 중단하고 기존 요약·사용량과 최근 대화 기억은 유지합니다.
- 동의를 철회한 동안 완료된 분석과, 이전 동의를 사용하던 분석이 재동의 후 늦게 돌아온 결과를 저장하지 않습니다. 회원 행 잠금과 동의 시각 비교로 DB 저장 시점에도 확인합니다.
- 다시 켜면 재동의 이후 시작한 대화만 요약합니다. 반복 켜기 요청은 최초 동의 경계를 바꾸지 않습니다.
- 기존 기록 개별 삭제·월말 자동 발행 및 실제 음성/요약 품질 검증은 아직 남아 있습니다. 학습 요약 보유기간은 아래 3개월 결정이 적용됩니다.

## 2026-10-25 학습 요약 3개월 보관 확정

사용자가 선택지에서 **3개월**을 선택했습니다. 학습 요약·복습 표현·교정 내용은 저장 시점부터 한국시간의 달력 기준 3개월 동안 조회할 수 있습니다. 월말·윤년은 해당 월의 마지막 날로 맞춥니다. 기간이 지나면 본인 직접 조회(RLS)와 리포트에서 제외하고, 매일 한국시간 오전 5시 운영 DB에서 자동 정리합니다. 실제 삭제는 일일 작업 시점까지 최대 약 하루 지연될 수 있습니다.

이 기준은 결제·사용량·기존 화상수업·최근 대화 기억에 적용하지 않습니다. 따라서 오래된 달의 사용량은 표시되어도 복습 요약은 만료되어 표시되지 않을 수 있습니다. 보관 중인 기록 개별 삭제 UI, 월말 자동 발행·알림 및 실제 회화 검증은 별도 남은 작업입니다.

## 2026-10-25 월말 자동 발행 개발 — 활성화 보류

- 매일 한국시간 오전 0시 10분에 지난달의 정산 회화를 확인하여 월간 리포트 발행 기록을 생성하는 코드·마이그레이션을 작성했습니다. 월 첫날 발행하고 이후 일일 재시도하며 회원·월별 고유 키로 중복을 막습니다.
- 회원이 요약 저장에 동의하고 해당 월의 정산 회화가 있을 때만 발행합니다. 사이트 회화 화면에 대상 월과 리포트 링크를 표시합니다. 이메일·문자·외부 푸시는 보내지 않습니다.
- 발행 기록에는 발행 시점의 사용시간·학습일·연결 구간 수만 저장합니다. 학습 요약을 복사하지 않아 3개월 요약 보관 기간을 늘리지 않습니다. 발행 메타데이터도 3개월 뒤 자동 정리하도록 설계했습니다.
- **아직 DB에 적용하지 못했습니다.** Supabase apply_migration이 두 번 `Invalid or expired requestState`로 실패했고, 이후 읽기 조회에서 테이블·마이그레이션 이력·예약 작업이 모두 없음을 확인했습니다.
- `TALKLY_AI_MONTHLY_REPORTS_ENABLED`는 기본 꺼짐입니다. 꺼진 상태에서는 새 테이블을 조회하지 않아 기존 회화·리포트가 계속 작동합니다. DB 적용·실제 권한·스케줄 확인 후 preview에서만 활성화해야 합니다.
- 임시 PostgreSQL에서 연도 경계·대상 월 집계·동의·중복·RLS·만료·일일 스케줄을 검증했습니다. 실제 예약 발행과 로그인 후 안내 표시는 아직 미검증입니다.

## 회화 순서 보완 및 실제 음성 검증 대기

생각 중 해제 시 speech_stopped만 보고 응답을 요청하던 흐름을 교체했습니다. 의미 기반 VAD로 음성 확정을 감지하고, 클라이언트가 확정 입력·생각 중·발화 중·기존 응답 상태를 함께 확인하여 응답을 1회 요청합니다. 입력이 없는 침묵만으로 새 질문을 시작하지 않습니다. 자동 갱신에서는 확정됐지만 아직 응답 요청 전인 입력과 생각 중 상태를 전달합니다. Provider 오류가 오면 연결을 정리합니다.

가상 이벤트와 실제 클라이언트 이벤트 처리 함수 테스트는 통과했습니다. **실제 음성 품질이나 기다림이 검증된 것은 아닙니다.** `docs/TALKLY_AI_VOICE_QA.md`에 실제 기기 검증표를 추가했습니다. 첫 번째 런칭 단계는 실제 마이크·느린 답변·갱신 검증이 끝날 때까지 미완료로 유지합니다.

## 최신 변경: 생각 중 버튼 제거 및 자동 대기

사용자는 생각 중 버튼을 학습자가 누르는 방식이 회화의 편리성을 해친다고 판단하여 제거를 요청했습니다. 수동 생각 중/답변 준비됐어요 버튼과 관련 상태·API 입력을 제거했습니다. 일시정지/종료는 유지합니다.

확정된 음성 입력 뒤 짧은 자동 여유를 두고, 그 사이 다시 말하면 응답 예약을 취소합니다. 다음 발화가 확정되기 전에는 이전 입력을 근거로 성급하게 응답하지 않습니다. 짧은 단답·미완성 표현·최근 단답 패턴에는 더 여유를 주며 긴 문장은 더 빨리 응답합니다. 추가 AI 호출이나 장기 저장 없이 브라우저에서 처리합니다. 자동 대기 중에도 연결 시간은 차감됩니다.

최근 테스트는 코드/가상 타이머 검증이며 실제 음성 체감 검증은 미완료입니다. 과거 문서의 생각 중 버튼·수동 해제 지시는 이 변경으로 대체됩니다.

## 연결 장애 정리 보완

제어 채널 닫힘/오류, 마이크 track 종료, 소리 재생 거부도 정상 종료·정산 요청 흐름으로 연결했습니다. 연결 시작 중 실패와 이전 연결의 늦은 이벤트를 구분하고, lease 만료 직전 종료는 자동 갱신을 유지합니다. 마이크 권한 거부/입력 장치 없음 안내는 유지합니다.

가상 장치 테스트는 통과했지만 실제 헤드셋 분리·모바일 재생 정책·오프라인의 서버 정산 지연은 아직 미검증입니다. 네트워크가 완전히 끊기면 로컬 마이크/연결은 정리하되 서버 정산 즉시 성공을 보장하지 않으며, 확인 실패 안내와 watchdog 복구를 구분합니다.

## 최신 결정: 성인 먼저 런칭

사용자가 **성인 먼저**를 선택했습니다. 초기 AI는 만 19세 이상 본인 이용으로 안내합니다. 성인 자기확인과 현재 버전 AI 안내 동의가 없으면 가입/회화·이용권/새 요약 저장을 서버에서 제한합니다. 기존 AI 가입자의 재동의는 체험·이용권·정지·기억을 초기화하지 않습니다. 기존 토클리 회원가입·수업과는 별도입니다.

독립 PostgreSQL 테스트로 두 순서, 예약 유지/새 예약 차단, 중복 정산 환불 1회와 소유자/RPC 권한을 확인했습니다. 실제 서버 함수/라우트 실행 테스트로 begin-close→hangup→finish 순서, hangup 실패 시 정산 차단, 등록 0행의 provider 정리·409, 정상 등록의 watchdog 예약을 확인했습니다. 운영 실제 통화는 만들거나 종료하지 않았습니다. 이는 네트워크가 끊겨 provider 종료 자체를 확인할 수 없는 경우나 함수 강제 종료까지 해결한 영속 supervisor를 뜻하지 않습니다. 실제 마이크/장시간 통화 및 런타임 watchdog 검증은 여전히 남아 있습니다.
