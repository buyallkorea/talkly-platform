# TALKLY AI 재이용·재결제 안내

사용자 요청: 무료 체험 후 떠난 회원과 30일 이용권 만료 후 재결제하지 않은 회원에게 카카오톡 또는 메일로 안내하는 기능. **실제 발송은 비활성화이며 자동 발송 완료로 보지 않습니다.**

## 구현한 첫 단계

- 대상 판정의 순수 함수와 관리자 화면의 조건/문안 미리보기.
- 체험 후 안내: 성인 이용 확인을 마친 일반 회원, 체험 사용 이력 있음, 유료 구매 없음, 이용권 이력 없음, 마지막 정산 회화 후 24시간 경과. 총 3분 소진 전 중단한 사람도 포함하는 기본안.
- 만료 후 안내: 유료 결제 이력이 있고 이용권 만료 후 24시간 경과. 새 이용권 활성화·결제 확인 중·진행 중 회화는 제외.
- 관리자·강사·정지 회원·성인 이용 안내 확인 전 계정 제외. 체험 안내는 회원당 1회 키, 만료 안내는 만료 시각별 1회 키로 중복 판정. 발송 기록이 연결되기 전에는 중복 방지가 실제 운영에서 작동한다고 주장하지 않음.
- 채널별 광고 수신 동의를 구분하고, 연결된 허용 채널 한 곳만 선택하는 판정 함수. 둘 다 동의·준비된 경우 사용자 선택에 따라 카카오 우선. 실제 수신 동의는 아직 수집/저장하지 않음.
- 한국시간 09–18시에만 발송하도록 판정하는 기본안. 문안에 광고 표시·서비스 링크·운영 연락처·무료 수신거부 자리 표시자를 포함.

관리자 미리보기는 최근 회원100명·결제100건·해당 회원 연결1,000건만 읽는 표본입니다. 전체 대상 수나 예약 건수가 아닙니다. 기록 범위 밖 대상은 누락될 수 있으며, 현재 수신동의/발송 이력 저장이 연결되지 않아 실제 발송 가능 대상은 0명으로 표시합니다. 개인정보 연락처를 새로 읽거나 외부로 전송하지 않습니다.

## 기존 연동 조사

`lib/email.ts`의 기존 SMTP 메일 발송 기능과 `lib/solapi.ts`의 휴대폰 인증 SMS 기능이 있습니다. 기존 인증문자/일반 메일 코드는 변경하지 않았습니다. Kakao 브랜드 메시지는 SMS 연동만으로 사용할 수 없고 비즈니스 채널/제공업체 설정이 추가로 필요합니다.

카카오 공식 브랜드 메시지 가이드는 광고성 메시지 채널과 카카오 수신 동의를 설명합니다. 재이용/재구매 안내를 알림톡 정보성 메시지로 임의 발송하지 않습니다. SOLAPI 텍스트형 브랜드 메시지 API 문서를 확인했지만 실제 제공업체 호출 코드는 아직 연결하지 않았습니다.

## 영속 대기열과 중복 방지 (2026-10-25)

운영 DB에 `20261025095208_talkly_ai_outreach_outbox`를 적용했습니다. 서버 전용 RLS 테이블과 enqueue/claim/finish/expire 함수를 추가했습니다. 전화번호·이메일·메시지 본문은 대기열에 복사하지 않습니다. 체험 안내는 사용자당 한 이벤트, 만료 안내는 동일 이용권 만료시각당 한 이벤트이며 채널을 바꿔도 중복 등록하지 않습니다. pending/sending/accepted/failed/unknown/skipped 상태를 구별하며 accepted는 제공업체 접수로만 해석합니다. 자동 등록, 발송 worker, 제공업체 호출, cron은 연결하지 않았고 적용 후 운영 대기열 0건을 확인했습니다.

등록 및 claim 직전에 DB 전체 기록으로 회원 상태/성인 동의/학습회원 역할, 현재 채널 동의 버전과 revision, 회화 중 여부, 결제 확인 중 여부, 실제 유료 결제/만료 또는 마지막 유료 사용 없는 체험 활동과 24시간 경과를 다시 확인합니다. 여기서 유료 결제란 ai_payments.status=paid를 뜻하며 trial_used_seconds의 무료 체험 활동과 구별합니다. claim은 한국시간 09–18시에만 가능하고 회원/대기열 잠금으로 중복 처리를 막습니다. 철회/재동의로 revision이 바뀌면 기존 대기 건도 제외합니다.

claim_token이 일치하는 sending 상태만 결과를 기록할 수 있습니다. 5분 넘게 sending으로 남으면 expire 함수가 unknown으로 바꾸며 자동으로 pending으로 되돌리지 않습니다. 이 정리 함수를 주기적으로 호출하는 작업 역시 아직 연결하지 않았습니다. 실패/unknown 이벤트도 자동 재등록하지 않습니다. worker 연결 시 네트워크 호출 바로 전 연락처/동의 재확인, 제한 시간과 중단 처리를 추가해야 합니다. DB claim 이후 이미 제공업체로 넘어간 메시지는 철회로 회수할 수 없으며 외부 호출까지 원자적으로 보장한다고 주장하지 않습니다.

독립 PostgreSQL 테스트: 미동의, 다른 채널 중복, 교사/회화중/결제확인중 제외, 동의 철회, 갱신 후 제외, 결과 토큰과 종료 상태, 오래된 claim의 unknown 전환, 서버 전용 접근을 검증했습니다. KST 시간대에 따라 현재 실행한 주간/야간 분기를 검증하며 두 분기를 모두 실행했다고 주장하지 않습니다. 실 서비스 동시 worker 부하 및 실제 전달 검증은 미실행입니다. 보안 advisor의 RLS 정책 없음 INFO는 서버 전용 테이블의 의도된 기본 차단이며 일반 클라이언트 권한을 부여하지 않았습니다.

## 2026-10-26 로그인 없는 안내 수신거부

수신거부 확인 페이지와 POST API를 추가했다. 열람/GET만으로는 변경하지 않고 버튼 확인 후 링크의 채널만 철회한다. 로그인·AI 활성화·새 동의 활성화·회원 정상 상태를 요구하지 않는다. 기존 ai_set_outreach_consent로 설정과 감사 이력을 함께 갱신하며 반복 철회는 멱등 처리한다. 브라우저가 보낸 회원 ID/채널/동의 값은 대상으로 사용하지 않는다.

향후 발송 준비에서 사용할 링크 발급 helper는 현재 채널 동의가 있을 때만 256비트 임의 토큰을 생성한다. 원 토큰은 DB에 저장하지 않고 SHA-256 해시와 소유자/채널만 남긴다. 링크 토큰은 fragment에 두어 HTTP 요청·Referer 헤더에 포함되지 않게 하고 페이지에서 읽은 뒤 주소에서 제거한다. 같은 링크는 해당 채널 철회만 허용하며 재동의/회원 조회/결제 변경은 허용하지 않는다. 기존 링크를 다시 열어도 철회할 수 있도록 사용 후 토큰을 폐기하지 않으며, 토큰 기록은 AI 회원 삭제 시 같이 정리된다. 별도 보관 기준은 정식 발송 전 확정 대상이다.

발급 helper는 아직 발송 worker에 연결하지 않았다. 실제 고객용 링크 발급·고객 메시지 발송·신규 수신 동의 활성화는 실행하지 않았다. 카카오 발신프로필/검증된 연락처/최종 문안·발송 worker/스케줄과 이메일 List-Unsubscribe 프로토콜은 별도 잔여 작업이다. fragment 보존은 실제 카카오/이메일 링크를 통한 오픈 후 테스트가 필요하다. 이미 제공업체에 접수된 안내를 취소하는 기능은 아니다.

코드·가상 UI/API·독립 PostgreSQL에서 GET/초기 effect의 무변경, 로그인 없는 채널 철회, 토큰 원문 미저장, 원인 불명 실패의 성공 오표시 방지, 중복 클릭, 정지 회원·중복 철회·익명/회원 직접 DB 접근 차단을 검증했다. 발송 전 claim의 기존 동의 revision 확인은 유지한다.

## 2026-10-26 발송 대상의 인증 근거

향후 발송 worker가 사용할 서버 연락처 확인 helper를 추가했다. 기존 ai_outreach_eligible RPC로 역할/AI 상태/성인 동의/채널 동의 revision/재결제·재이용 여부를 확인한 뒤 Auth Admin API에서 확인 완료된 이메일/전화번호를 읽는다. 조회 이후에도 같은 적격 조건을 다시 확인한다. 익명·정지·삭제 계정, 미확인/잘못된 주소, 수정 가능한 user_metadata의 인증 표시는 근거로 쓰지 않는다. 실제 연락처를 로그나 관리자 목록에 출력하지 않는다.

TALKLY 신규 가입은 이미 검증·consume한 가입 OTP의 전화번호 해시와 인증 시각을 서버 관리 app_metadata에 기록하도록 연결했다. 기존 가입 단계·문자 횟수·이메일 확인·역할·OTP 재사용 차단은 유지하며 별도 광고 동의를 만들지 않는다. 발송 확인은 현재 profiles.phone과 서버 인증 근거가 일치할 때만 허용한다. 프로필을 미인증 번호로 변경하면 발송 대상으로 사용하지 않는다. 전화번호 원문이나 OTP를 새 인증 근거에 복제하지 않는다. 전화번호 해시는 익명 데이터라는 주장이 아니며 보관 기준은 판매/발송 개시 전 정책에 포함해야 한다.

기존 회원 중 이 서버 인증 근거가 없는 번호는 자동 인증 처리하지 않는다. 기존 번호를 신뢰할 수 있는 방식으로 연결하거나 필요한 경우 기존 OTP를 재사용하는 확인 흐름이 별도로 필요하다. 사용자에게 추가 인증을 일괄 요구하거나 실제 인증 문자를 보내지는 않았다.

공통 admin client에는 선택적인 요청 제한 시간을 추가했고 인수가 없는 기존 호출 설정은 유지했다. 새 연락처 확인만 3초 fetch 제한을 사용하며 기존 취소 신호도 보존한다. 현재 helper는 발송 worker에 연결 전이며 고객 연락처 조회/실제 발송은 실행하지 않았다.

검증: 실제 가입 handler의 가상 실행에서 검증된 OTP 이후에만 서버 근거 추가, 브라우저 app_metadata 무시, 역할·이메일 확인 유지, 만료/중복 OTP 차단을 확인했다. 기존 가입 확인 이메일 테스트 5건도 통과했다. 주소 주입/가짜 인증 정보/가입 번호 변경/동의 철회 경합/조회 실패 및 client 기본 설정·취소 신호를 모형 데이터로 검증했다.
