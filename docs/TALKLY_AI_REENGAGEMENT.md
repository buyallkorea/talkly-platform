# TALKLY AI 재이용·재결제 안내

사용자 요청: 무료 체험 후 떠난 회원과 30일 이용권 만료 후 재결제하지 않은 회원에게 카카오톡 또는 메일로 안내하는 기능. **실제 발송은 비활성화이며 자동 발송 완료로 보지 않습니다.**

## 구현한 첫 단계

- 대상 판정의 순수 함수와 관리자 화면의 조건/문안 미리보기.
- 체험 후 안내: 성인 이용 확인을 마친 일반 회원, 체험 사용 이력 있음, 유료 구매 없음, 이용권 이력 없음, 마지막 정산 회화 후 24시간 경과. 총 3분 소진 전 중단한 사람도 포함하는 기본안.
- 만료 후 안내: 유료 결제 이력이 있고 이용권 만료 후 24시간 경과. 새 이용권 활성화·결제 확인 중·진행 중 회화는 제외.
- 관리자·강사·정지 회원·성인 이용 안내 확인 전 계정 제외. 체험 안내는 회원당 1회 키, 만료 안내는 만료 시각별 1회 키로 중복 판정. 발송 기록이 연결되기 전에는 중복 방지가 실제 운영에서 작동한다고 주장하지 않음.
- 채널별 광고 수신 동의를 구분하고, 연결된 허용 채널 한 곳만 선택하는 판정 함수. 둘 다 동의·준비된 경우 사용자 선택에 따라 카카오 우선. 실제 수신 동의는 아직 수집/저장하지 않음.
- 한국시간 09–18시에만 발송하도록 판정하는 기본안. 문안에 광고 표시·서비스 링크·운영 연락처·무료 수신거부 자리 표시자를 포함.

관리자 미리보기는 최근 회원100명·결제100건·해당 회원 연결1,000건만 읽는 표본입니다. 전체 대상 수나 예약 건수가 아닙니다. 기록 범위 밖 대상은 누락될 수 있으며, 현재 수신동의/발송 이력 저장이 연결되지 않아 실제 발송 가능 대상은 0명으로 표시합니다. 개인정보 연락처를 새로 읽거나 외부로 전송하지 않습니다.

## 기존 연동 조사

`lib/email.ts`의 기존 SMTP 메일 발송 기능과 `lib/solapi.ts`의 휴대폰 인증 SMS 기능이 있습니다. 기존 인증문자/일반 메일 코드는 변경하지 않았습니다. Kakao 브랜드 메시지는 SMS 연동만으로 사용할 수 없고 비즈니스 채널/제공업체 설정이 추가로 필요합니다.

카카오 공식 브랜드 메시지 가이드는 광고성 메시지 채널과 카카오 수신 동의를 설명합니다. 재이용/재구매 안내를 알림톡 정보성 메시지로 임의 발송하지 않습니다. SOLAPI 텍스트형 브랜드 메시지 API 문서를 확인했지만 실제 제공업체 호출 코드는 아직 연결하지 않았습니다.

## 다음 개발 및 설정

1. AI 전용 이메일/카카오 광고 수신동의 및 변경 이력 저장. 필수 가입/성인 동의와 분리하고 기본 꺼짐. 기존 토클리 수신 동의를 자동 전용하지 않음.
2. 사용자가 언제든 채널별 수신거부 가능하도록 실제 링크/화면·연락처 변경/동의 철회 처리.
3. 전체 회원을 대상으로 최신 상태를 조회하는 DB 작업과 영속 발송 대기열·중복 키·발송 상태(예약/처리/접수/성공/실패/취소/불명) 기록. 실제 발송 직전에 재결제/최근 활동/동의를 재확인.
4. SMTP 및 카카오 채널 실제 설정, 광고 표시·연락처·무료 수신거부 방법과 문안 검토. SMTP 접수와 실제 배달을 구분하며, 발송 결과가 불명확하면 자동 재시도/다른 채널 대체 발송으로 중복시키지 않음.
5. 관리자 미리보기·본인 테스트·실패/수신거부/재결제/동시 작업 검증 후 실제 발송 활성화.

현재 월말 발행에서도 DB 변경 도구의 requestState 오류가 지속되어 신규 동의/발송 스키마 적용을 진행하지 않았습니다. 이 첫 단계에는 발송 API 호출, 새 외부 서비스 설치, 실제 메시지 전송이 없습니다.

## 검증

`node tests/talkly-ai/reengagement.mjs`: 대상 조건·제외·24시간 경계·수신동의·단일 채널·중복 키·주간 시간·문안 필수 자리 표시자 검증. 실제 저장/발송/배달은 검증되지 않음.

공식 참고: https://www.kisa.or.kr/402/form?postSeq=2577 ; https://kakaobusiness.gitbook.io/main/ad/brandmessage ; https://solapi.com/developers/api/kakao-bms-free-text . 현재 안내는 구현 설계이며 법적 적합성 완료를 주장하지 않습니다.

## 채널 우선순위 결정

사용자가 **카카오톡 먼저**를 선택했습니다. 코드의 준비된 동의 채널 우선순위도 카카오로 맞췄습니다. 실제 발송은 여전히 OFF입니다. 소스와 조회 가능한 Vercel 설정에서는 SOLAPI 인증문자 운영 키 이름만 확인됐고, 카카오 비즈니스 채널 주소·발신프로필 pfId·브랜드 메시지 연결은 확인되지 않았습니다. 키 값은 읽거나 복사하지 않았습니다.

사용자는 토클리에 이미 설정된 연동을 재사용하도록 요청했습니다. 신규 채널 개설이나 주소 재요청보다 기존 SOLAPI 계정의 발신프로필 확인을 우선합니다. 2026-10-25 운영 환경변수 이름만 재확인하여 SOLAPI 키·시크릿·발신번호의 production 등록을 확인했습니다. 코드 및 환경변수 목록만으로 SOLAPI 콘솔에 연결된 카카오 프로필 유무를 판단할 수는 없습니다. 관리자 화면은 현재 배포의 기존 SOLAPI 설정 유무만 표시하고, 카카오 승인/실제 연결 완료로 표시하지 않습니다. 운영 키를 테스트 배포로 복사하거나 실제 발송하지 않았습니다.


## 2026-10-25 수신 동의 저장 기반

운영 DB에 `20261025092634_talkly_ai_outreach_consent`를 적용했습니다. `ai_outreach_preferences`는 카카오/이메일을 분리하며 기본 미동의, `ai_outreach_consent_events`는 변경 이력을 원자적으로 기록합니다. 기존 회원의 동의를 가져오지 않았으며 두 테이블 모두 검증 시 0건입니다. 소유자만 설정을 조회하고, 변경 함수와 이력은 서비스 역할만 접근합니다. 회원 행 잠금으로 변경을 직렬화하고 동일 설정 재저장은 이력을 늘리지 않습니다. 정지 회원도 철회할 수 있고 새 동의는 차단합니다.

독립 PostgreSQL 테스트로 기본 미동의·채널 분리·동일 요청·철회·역할/소유자 격리를 확인했습니다. 운영에서 실제 회원 동의 변경은 실행하지 않았습니다. 사용자 동의 UI/API, 고지 확정, 수신 주소 검증, 발송 대기열/중복 방지/무료 수신거부와 제공업체 연결은 아직 미완료입니다. 새 함수에 향후 API를 연결할 때 사용자 ID는 인증 세션에서만 가져오고, 신규 동의에 현재 성인 동의/채널 고지 버전을 검증해야 합니다. 관리자 설정 표시는 키 값이 아닌 현재 배포 내 등록 유무만 표시하며 제공업체의 실제 승인 상태는 검증하지 않습니다.


## 회원 수신 설정 화면 및 API

`/talkly-ai/notifications`와 `/api/talkly-ai/notifications`를 추가했습니다. 회화 화면에서 설정으로 이동하며 로그인한 본인의 채널별 설정만 읽고 저장합니다. POST는 기존 동일 출처 검증을 거치며 사용자 ID는 서버 인증 세션에서 가져옵니다. 채널/불리언을 엄격히 검증하고 응답은 캐시하지 않습니다. 철회는 현재 성인 동의/활성 상태를 요구하지 않습니다. DB 함수는 회원 존재를 확인합니다.

신규 동의는 `TALKLY_AI_OUTREACH_OPT_IN_ENABLED=true`일 때만 API와 화면에서 허용하도록 했으며 현재 환경변수는 설정하지 않아 OFF입니다. 켜기 전 최종 고지, 연락처 사용/검증, 카카오 프로필, 무료 수신거부와 이력 보관 정책 검토가 필요합니다. 신규 동의가 켜져도 현재 성인 동의와 활성 회원 및 student/parent 역할, 고지 버전을 검증합니다. 실제 발송 활성화와는 독립적이며 발송 코드는 연결하지 않았습니다.

실제 라우트 실행 테스트로 기본 신규 동의 차단, 소유자 강제, 엄격한 입력, 버전/역할 검사, 구버전 회원 철회 경로와 DB 실패 처리를 확인했습니다. 실제 브라우저 로그인/클릭 및 고객 메시지 전달 검증은 아직 실행하지 않았습니다.
